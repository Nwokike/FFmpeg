# h11 0.16.0 — Complete API Reference

> Pure-Python, bring-your-own-I/O implementation of HTTP/1.1 (RFC 7230).
> Contains **zero networking code**: the app feeds raw socket bytes in via
> `receive_data()` and gets wire bytes out via `send()`. State machine is
> symmetric for both roles. ~800 LOC, 11 `.py` files, **zero runtime
> dependencies** (stdlib only). Typing: ships `py.typed`.

### `h11._util` — errors, sentinels, coercions

```python
class ProtocolError(Exception):
    def __init__(self, msg: str, error_status_hint: int = 400) -> None: ...

    error_status_hint: int  # suggested HTTP status for a server replying to this error; default 400
    # NOTE: cannot instantiate directly -> TypeError ("tried to directly instantiate ProtocolError")


class LocalProtocolError(ProtocolError):
    def _reraise_as_remote_protocol_error(
        self,
    ) -> NoReturn: ...  # internal: flips self.__class__ to Remote


class RemoteProtocolError(ProtocolError): ...


def validate(
    regex: Pattern[bytes], data: bytes, msg: str = "malformed data", *format_args: Any
) -> Dict[str, bytes]: ...
def bytesify(
    s: bytes | bytearray | memoryview | str,
) -> bytes: ...  # str -> ascii-encoded; int -> TypeError


class Sentinel(
    type
): ...  # metaclass giving NEED_DATA-style singletons: type(x) is x, repr(x) == name
```

Error-handling contract (see `Connection.next_event`/`send`): any exception
from `next_event()` forces `their_state = ERROR`; any from `send()` forces
`our_state = ERROR`. `LocalProtocolError` = **you** broke the rules (bad call
order, bad constructor args); `RemoteProtocolError` = **peer** sent bad bytes
(raised only from `next_event()`; internally readers raise `LocalProtocolError`
and `next_event()` converts via `_reraise_as_remote_protocol_error`).

### `h11._events` — event classes (all frozen dataclasses, `__hash__ = None`)

```python
class Event(ABC): ...  # base, __slots__ = ()

class Request(Event):
    def __init__(self, *, method: bytes | str, target: bytes | str,
                 headers: Headers | list[tuple[bytes|str, bytes|str]],
                 http_version: bytes | str = b"1.1", _parsed: bool = False) -> None
    method: bytes; target: bytes; headers: Headers; http_version: bytes
    # Validates: HTTP/1.1 REQUIRES exactly one Host header (0 or 2+ -> LocalProtocolError);
    # method must match `token`, target must match visible-printing-chars.

class InformationalResponse(Event):   # via _ResponseBase
    def __init__(self, *, headers, status_code: int, http_version: bytes | str = b"1.1",
                 reason: bytes | str = b"", _parsed: bool = False) -> None
    # status_code MUST satisfy 100 <= status_code < 200 else LocalProtocolError.
    # NOTE: 1xx responses never carry a body and never change body-framing state;
    # any number may precede a final response (all seen in SEND_RESPONSE state).

class Response(Event):                # via _ResponseBase
    # Same signature as InformationalResponse.
    # status_code MUST satisfy 200 <= status_code < 1000 else LocalProtocolError.
    # (Upper bound 1000, not 599 — accepts non-standard 7xx/8xx/9xx.)

class Data(Event):
    def __init__(self, data: bytes, chunk_start: bool = False, chunk_end: bool = False) -> None
    # data: body chunk. chunk_start/chunk_end are OUTPUT-ONLY markers set by ChunkedReader
    # on receive; IGNORED on send. For sendfile support see send_with_data_passthrough.

class EndOfMessage(Event):
    def __init__(self, *, headers: Headers | list | None = None, _parsed: bool = False) -> None
    # headers: trailers, default []. MUST be empty unless Transfer-Encoding: chunked.

class ConnectionClosed(Event): ...    # no fields; half-close aware (see Gotchas)
```

**h2-style informational rules:** like h2, 1xx are interim only — but unlike
h2 there is no `END_HEADERS`/`END_STREAM` flag model; framing is inferred from
headers per RFC 7230 §3.3.3 (see `_body_framing` below). `101 Switching
Protocols` and `CONNECT 2xx` are the only responses that divert the state
machine to `SWITCHED_PROTOCOL` (and only if the client previously proposed the
switch).

### `h11._headers` — header handling rules

```python
CONTENT_LENGTH_MAX_DIGITS = 20


class Headers(Sequence[tuple[bytes, bytes]]):
    def raw_items(self) -> list[tuple[bytes, bytes]]: ...  # original casing

    # Iteration/indexing yields (lowercased-name, value). Preserves order + duplicates.


def normalize_and_validate(headers, _parsed: bool = False) -> Headers: ...
def get_comma_header(
    headers: Headers, name: bytes
) -> list[bytes]: ...  # comma-split, lowercased, stripped
def set_comma_header(headers: Headers, name: bytes, new_values: list[bytes]) -> Headers: ...
def has_expect_100_continue(request: Request) -> bool: ...  # False for HTTP/1.0
```

Normalization/validation rules enforced on **every** `Request`/`Response`
construction and every parsed header line:

1. Names: ASCII `token`, lowercased for comparison (original case kept for the wire; `Host` is re-emitted first on send).
2. Values: optional surrounding whitespace stripped (OWS); interior allows obs-text (`\x80–\xFF`) and some controls (e.g. `\x01` for real-world cookies — gh-57) but **never NUL or whitespace-only tricks**.
3. `Content-Length`: all occurrences (incl. comma-joined) must agree on one value or `LocalProtocolError("conflicting Content-Length headers")`; must be all-digits, ≤ 20 digits.
4. `Transfer-Encoding`: at most one header, value must be exactly `chunked` (case-insensitive) or `LocalProtocolError` with `error_status_hint=501`; anything else (gzip, compress…) is rejected.
5. Obsolete line folding (`obs-fold`, CRLF + SP/HTAB continuation) is unfolded with a space on receipt.

### `h11._abnf` — grammar (regex fragments, not a public API)

`OWS`, `token`, `field_name`, `field_value` (with RFC 7230 erratum 4189 fix),
`header_field` (named groups `field_name`/`field_value`), `method`,
`request_target` (visible chars), `http_version`, `request_line`
(`method SP target SP HTTP/x.y`), `status_line` (`HTTP/x.y SP ddd [SP reason]`,
reason optional for lenient servers), `chunk_header` (hex size ≤ 20 digits +
optional `;ext`, tolerant of trailing OWS).

### `h11._state` — states, roles, transition tables

```python
# Roles
class CLIENT(Sentinel, metaclass=Sentinel): ...


class SERVER(Sentinel, metaclass=Sentinel): ...


# Per-role states
class IDLE(Sentinel, metaclass=Sentinel): ...  # ready for new message head


class SEND_RESPONSE(Sentinel, metaclass=Sentinel): ...  # server-only: head received, response due


class SEND_BODY(Sentinel, metaclass=Sentinel): ...  # message head done, body streaming


class DONE(Sentinel, metaclass=Sentinel): ...  # message complete, awaiting start_next_cycle


class MUST_CLOSE(Sentinel, metaclass=Sentinel): ...  # message complete, connection must close


class CLOSED(Sentinel, metaclass=Sentinel): ...  # EOF sent/received


class ERROR(Sentinel, metaclass=Sentinel): ...  # protocol violation (terminal)


# Upgrade states
class MIGHT_SWITCH_PROTOCOL(Sentinel, metaclass=Sentinel): ...


class SWITCHED_PROTOCOL(Sentinel, metaclass=Sentinel): ...
```

Event-triggered transitions (`EVENT_TRIGGERED_TRANSITIONS`):

```text
CLIENT:  IDLE --Request--> SEND_BODY
         IDLE --ConnectionClosed--> CLOSED
         SEND_BODY --Data--> SEND_BODY --EndOfMessage--> DONE
         DONE/MUST_CLOSE/CLOSED --ConnectionClosed--> CLOSED
SERVER:  IDLE --(Request from CLIENT)--> SEND_RESPONSE
         IDLE --ConnectionClosed--> CLOSED | IDLE --Response--> SEND_BODY (edge case)
         SEND_RESPONSE --InformationalResponse--> SEND_RESPONSE (loop)
         SEND_RESPONSE --Response--> SEND_BODY
         SEND_RESPONSE --(101+upgrade-proposal)--> SWITCHED_PROTOCOL
         SEND_RESPONSE --(2xx-to-CONNECT-proposal)--> SWITCHED_PROTOCOL
         SEND_BODY --Data--> SEND_BODY --EndOfMessage--> DONE
         DONE/MUST_CLOSE/CLOSED --ConnectionClosed--> CLOSED
```

State-triggered (automatic, no event): `DONE -> MIGHT_SWITCH_PROTOCOL` when a
client switch proposal is pending (takes priority over `DONE -> MUST_CLOSE`);
`MIGHT_SWITCH_PROTOCOL -> DONE` if proposals withdrawn; `DONE -> MUST_CLOSE`
for either role once keep-alive is disabled; plus joint close/error couplings
(e.g. `(CLOSED, DONE) -> SERVER=MUST_CLOSE`). Full ASCII cycle for the common
client-GET-keep-alive case:

```text
CLIENT: IDLE --send(Request)--> SEND_BODY --send(EndOfMessage)--> DONE
        --start_next_cycle()--> IDLE --...                         (repeats)
SERVER: IDLE --receive(Request)--> SEND_RESPONSE --receive(Response)--> SEND_BODY
        --receive(Data)*--> --receive(EndOfMessage)--> DONE --start_next_cycle()--> IDLE
CLOSE:  either DONE --(Connection: close seen)--> MUST_CLOSE --ConnectionClosed--> CLOSED
ERROR:  any state --(violation)--> ERROR  (terminal; connection unusable)
```

`ConnectionState` internals: `states: {CLIENT: …, SERVER: …}`,
`keep_alive: bool` (starts `True`, one-way latch to `False`),
`pending_switch_proposals: set({_SWITCH_UPGRADE, _SWITCH_CONNECT})`;
methods `process_event()`, `process_error()`, `process_keep_alive_disabled()`,
`process_client_switch_proposal()`, `start_next_cycle()` (requires exactly
`{CLIENT: DONE, SERVER: DONE}`).

### `h11._connection` — `Connection` (full signatures)

```python
DEFAULT_MAX_INCOMPLETE_EVENT_SIZE = 16 * 1024

class Connection:
    def __init__(self, our_role: CLIENT | SERVER,
                 max_incomplete_event_size: int = DEFAULT_MAX_INCOMPLETE_EVENT_SIZE) -> None
    # our_role invalid -> ValueError. Sets their_role to the opposite,
    # their_http_version=None, _request_method=None, client_is_waiting_for_100_continue=False.

    # --- introspection (properties) ---
    @property
    def states(self) -> dict[role, state]: ...          # {CLIENT: ..., SERVER: ...}
    @property
    def our_state(self) -> state: ...
    @property
    def their_state(self) -> state: ...
    @property
    def they_are_waiting_for_100_continue(self) -> bool: ...
    @property
    def trailing_data(self) -> tuple[bytes, bool]: ...  # (unprocessed bytes, recv-closed flag)

    # --- public attributes (read-mostly) ---
    our_role; their_role; their_http_version: bytes | None
    client_is_waiting_for_100_continue: bool

    # --- receive path ---
    def receive_data(self, data: bytes) -> None: ...
        # Appends to buffer. b"" means EOF (sets _receive_buffer_closed).
        # b"" twice is fine; non-empty AFTER b"" -> RuntimeError.

    def next_event(self) -> Event | NEED_DATA | PAUSED: ...
        # Returns next parsed event (Request/Response/InformationalResponse/Data/
        # EndOfMessage/ConnectionClosed), or NEED_DATA (feed more bytes) or PAUSED
        # (peer finished its cycle / protocol switched — call start_next_cycle or
        # read trailing_data). Raises RemoteProtocolError on peer violation
        # (their_state -> ERROR). Oversized head (> max_incomplete_event_size) ->
        # RemoteProtocolError with error_status_hint=431.

    # --- send path ---
    def send(self, event: Event) -> bytes | None: ...
        # Serializes event, advances our state. Returns bytes to write to socket.
        # Returns None ONLY for ConnectionClosed. Raises LocalProtocolError
        # (our_state -> ERROR) on misuse.
    def send_with_data_passthrough(self, event: Event) -> list[bytes] | None: ...
        # Same, but returns list of byte-chunks; for Data events the list contains
        # the EXACT object passed as Data.data (sendfile support: any len()-able object).
    def send_failed(self) -> None: ...
        # Call if the socket write failed -> our_state = ERROR immediately.

    # --- cycling ---
    def start_next_cycle(self) -> None: ...
        # Resets both roles DONE -> IDLE for keep-alive/pipelining. Anything else
        # -> LocalProtocolError. Clears _request_method.
```

Body-framing selection (`_body_framing(request_method, event)`,
RFC 7230 §3.3.3), in priority order:

1. No-body responses → `("content-length", (0,))`: `204`, `304`, `HEAD`
   requests, `CONNECT` + 2xx. (1xx never reach here — separate class.)
2. `Transfer-Encoding` present → must be exactly `chunked` → `("chunked", ())`.
3. `Content-Length: N` → `("content-length", (N,))`.
4. Fallback: `Request` → empty body `(0,)`; `Response` → read-to-EOF
   `("http/1.0", ())` (close-delimited).

Keep-alive rule (`_keep_alive`): close if `Connection: close` seen **or** peer
is HTTP/1.0 (h11 deliberately offers **no** HTTP/1.0 keep-alive). Response-send
cleanup (`_clean_up_response_headers_for_sending`, server side only):
auto-selects `Transfer-Encoding: chunked` vs close-delimited for unknown-length
bodies based on peer version, strips contradictory `Content-Length`, and forces
`Connection: close` when keep-alive is off.

Minimal client example:

```python
import socket, h11

conn = h11.Connection(h11.CLIENT)
sock = socket.create_connection(("example.com", 80))
sock.sendall(
    conn.send(
        h11.Request(
            method="GET", target="/", headers=[("Host", "example.com"), ("Connection", "close")]
        )
    )
)
sock.sendall(conn.send(h11.EndOfMessage()))
while True:
    event = conn.next_event()
    if event is h11.NEED_DATA:
        data = sock.recv(4096)
        conn.receive_data(data)  # b"" on EOF
        continue
    if event is h11.PAUSED or isinstance(event, h11.ConnectionClosed):
        break
    print(type(event).__name__, event)
    if isinstance(event, h11.EndOfMessage):
        break
```

Cycle rules: after each full request/response both sides sit in `DONE`;
pipelining/keep-alive requires `start_next_cycle()` before the next head.
`send(ConnectionClosed())` → returns `None`, transitions `our_state` to
`CLOSED`/`MUST_CLOSE` path.

### `h11._readers` / `h11._writers` — wire codecs

`READERS` keys: `(CLIENT, IDLE)` → request-line reader;
`(SERVER, IDLE)` + `(SERVER, SEND_RESPONSE)` → status-line reader (1xx →
`InformationalResponse`, ≥200 → `Response`); `SEND_BODY` → framing factory
`{"chunked": ChunkedReader, "content-length": ContentLengthReader,
"http/1.0": Http10Reader}`; `DONE/MUST_CLOSE/CLOSED` (both roles) →
`expect_nothing` (any further bytes → `LocalProtocolError`, surfaced as
`RemoteProtocolError`). `ContentLengthReader.read_eof` / `ChunkedReader.read_eof`
raise `RemoteProtocolError("peer closed connection without sending complete
message body…")`; `Http10Reader.read_eof` returns `EndOfMessage` (EOF **is**
the terminator). `WRITERS` mirrors this; writers send `HTTP/1.1` unconditionally
(`I only send HTTP/1.1` if event claims otherwise).

**(a) Chain role of h11:** inside httpcore's connection loop, one
`h11.Connection(h11.CLIENT)` per socket tracks request/response state,
serializes the `GET` head (`send(Request)` + `send(EndOfMessage)`), and parses
the status line/headers/body (`receive_data`/`next_event`) including
`Content-Length` vs `chunked` framing of `version.json`, keep-alive reuse
across checks, and `Connection: close` handling.

**(b) MISUSE: none.** No direct import, no manual `Connection`, no hand-rolled
framing, no header construction that could trip h11 validators. Nothing to fix.

**(c) UNDERUSE / boundary:** the app uses ~1% of h11's surface (client GET,
200 + JSON) through two layers of abstraction — that is the correct posture.
The h11/httpcore boundary owns: malformed status lines, conflicting
`Content-Length`, non-`chunked` transfer codings, premature EOF, header-size
limits, and connection-reuse bookkeeping. The app owns: the 4 s timeout, the
`status_code == 200` gate, JSON shape validation, and the blanket
`except Exception → silent skip` policy.

## Considerations for v1

1. **Why h11 and not httptools/llhttp?** Not our choice to make — it arrives
   via `httpcore>=h11 0.16` as the default HTTP/1.1 engine. For this workload
   (one tiny JSON GET per launch, background) h11's pure-Python speed is
   irrelevant (microseconds against a 4 s network budget); its value is
   correctness conservatism (strict RFC 7230 validation, 100% branch-coverage
   test suite upstream) and zero native deps (no compiler needed in the
   Flet/mobile-packaging pipeline — llhttp/httptools would add a C build
   step). No action.
2. **HTTP/1.1-only implications:** h11 speaks only HTTP/1.1. The update host
   serves HTTP/1.1 (and ALPN will negotiate it even where h2 exists), so
   update checks work everywhere. Worst case vs HTTP/2 is one extra
   round-trip on a cold 2 KB fetch — immaterial. The `h2` extra is absent, so
   there is not even a code path to audit. Ship as-is.
3. **Malformed-server behavior:** any spec violation (bad status line,
   conflicting lengths, truncated body, oversize head) surfaces inside
   httpcore as a `RemoteProtocolError`-derived transport error, which httpx
   wraps (`httpx.TransportError` family) — and `check_for_updates()` already
   catches `Exception` and returns `None` (silent skip). A hostile or broken
   manifest host therefore degrades to "no update offered," never a crash or
   a corrupt install prompt. Correct for v1; do not narrow the `except`.
4. **Timeout interplay:** `timeout=4.0` lives in the anyio/httpx layer
   *above* h11 (h11 has no timers at all — `NEED_DATA` waits forever if you
   let it). httpcore cancels the socket read, so a slowloris-style dribble
   from the server cannot hang startup past ~4 s. The 16 KiB
   `max_incomplete_event_size` head cap additionally bounds memory while
   waiting. No change needed; just never move the update check onto a raw
   h11 socket without re-adding a timeout.
5. **Should the app care about h11 directly?** No. Pinning: consider adding a
   floor (`h11>=0.16`) to the app's own requirements only as documentation —
   httpcore already enforces it, and an explicit pin risks version-conflict
   noise at packaging time. For v1, the only h11-adjacent item worth a test
   is the existing behavior "server returns garbage → `None`, no dialog" —
   a one-case mock test at the httpx level, not h11 level.

## Gotchas

1. **No `StatusCode` enum, no `NORMAL`, no `bring_the_house_down`.**
   Status codes are plain `int` (accepts `http.HTTPStatus` via `int()` cast);
   `Response` allows up to 999. Don't write `h11.StatusCode.OK` — it doesn't exist.
2. **`send()` returns `None` only for `ConnectionClosed`.** Every other event
   returns `bytes` (possibly `b""`). Forgetting the `None` check breaks
   half-close flows.
3. **`b""` to `receive_data()` means EOF — permanently.** After EOF, further
   non-empty data raises `RuntimeError`. Never forward a "no data yet"
   empty-read from a non-blocking socket.
4. **`next_event()` has THREE outcomes:** event, `NEED_DATA` (read more),
   `PAUSED` (cycle over or protocol switch — call `start_next_cycle()` or
   inspect `trailing_data`). Treating `PAUSED` as fatal aborts keep-alive.
5. **`start_next_cycle()` requires exactly `{CLIENT: DONE, SERVER: DONE}`.**
   Anything else (notably `MUST_CLOSE` after `Connection: close`) raises
   `LocalProtocolError` — you must open a new connection instead.
6. **Errors are terminal.** After any `LocalProtocolError`/`RemoteProtocolError`
   the offending direction is `ERROR` forever; the `Connection` object is
   scrap metal — discard it, don't retry on it.
7. **h11 only *sends* HTTP/1.1.** `write_request`/`write_any_response` raise
   `I only send HTTP/1.1` for other versions; it *receives* 1.0 (then forces
   close-delimited bodies + `MUST_CLOSE`).
8. **`Transfer-Encoding` other than `chunked` is rejected** (501 hint);
   multiple `Host` headers or missing `Host` on 1.1 → error; trailers only
   with `chunked`; `Data` with `chunk_start/chunk_end` flags is receive-only
   metadata. All of these are httpcore's problem, not the app's — listed here
   so nobody "fixes" them at the app layer.
9. **100-continue / upgrades / CONNECT are inert for this app** but present in
   the machine: `client_is_waiting_for_100_continue`,
   `they_are_waiting_for_100_continue`, `trailing_data`,
   `MIGHT_SWITCH_PROTOCOL`/`SWITCHED_PROTOCOL`. `GET version.json` never
   triggers them; if reuse ever extends to WebSockets/proxies, re-read
   `_state.py` first.
